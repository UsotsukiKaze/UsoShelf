## 1. 产品定位与边界

JmShelf 是单用户、本地优先的漫画书架与阅读器。Windows 端以本地 Web 应用为核心，通过无标题栏 WebView2 窗口提供桌面体验；开发时也可以直接在浏览器访问本地 FastAPI 服务。相邻的 `JmShelf-Android` 是独立安装包，复用产品模型和大部分 Web UI，但拥有自己的 Android 外壳、Python 后端副本和存储策略。

当前产品负责：

- 扫描和管理已有图片目录。
- 查询 JM 元数据、登录账号并读取收藏；JMonline 提供画像推荐、榜单、分类浏览和高级在线搜索。
- 将在线条目加入书架并缓存以供在线阅读。
- 显式下载作品用于长期离线保存。
- 管理普通本子、JM 来源系列、自建系列和多级收藏夹。
- 提供连续、单页、双页三种阅读模式与跨话阅读。
- 保存阅读进度、昵称、备注、封面和封面隐私设置。
- 检查 JM 系列更新，以及检查和安装 JmShelf 自身更新。
- 在 Windows 上提供单实例、托盘、原生窗口控制、文件选择和资源管理器联动。

当前明确不负责：

- 多用户、局域网共享或云同步。
- 远程公开服务；后端只应监听回环地址。
- DRM、内容授权或第三方来源规则的稳定性保证。
- 将完整第三方图标库打进安装包。

## 2. 总体运行架构

```text
Windows 桌面模式

JmShelf.exe
  ├─ SingleInstance：Windows Mutex，重复启动时激活既有窗口
  ├─ Uvicorn/FastAPI：后台线程，绑定 127.0.0.1 随机空闲端口
  │   ├─ LibraryDatabase：SQLite + WAL
  │   ├─ JmcomicProvider：查询、收藏、封面、下载
  │   ├─ DownloadQueue：长期下载队列，2 个工作线程
  │   ├─ DownloadQueue：阅读缓存队列，2 个工作线程
  │   ├─ SeriesUpdateChecker：启动检查 + 每日检查
  │   └─ AppUpdateManager：应用更新检查、下载与暂存
  ├─ pywebview/EdgeChromium：加载本地 HTTP UI
  │   ├─ public/index.html
  │   ├─ public/styles.css
  │   └─ public/app.js
  ├─ DesktopApi：窗口拖动、缩放、最小化、最大化、关闭
  └─ JmShelfUpdater.exe：独立进程替换程序文件并支持回滚
```

```text
开发浏览器模式

uv run --no-sync jmshelf
  └─ Uvicorn 127.0.0.1:17318
      ├─ /api/*    JSON API
      ├─ /media/*  封面与漫画页
      └─ /*         public 静态页面
```

```text
主要数据流

用户操作
  → app.js 统一事件分发
  → fetch('/api/...', X-JmShelf-Request: 1)
  → main.py 路由/业务编排
  → db.py / provider.py / downloads.py / updates.py
  → SQLite、应用数据目录、JM 网络接口或 Windows 原生能力
  → JSON/媒体响应
  → 前端 state 更新并重新渲染局部 UI
```

### 3.2 Android 相邻项目

Android 项目位于 `D:\A_Projects\JmShelf-Android`，不是 Windows 项目的运行依赖。主要技术为：

- AndroidX Activity / WebKit / DocumentFile。
- Java 17，最低 API 24，目标 API 35。

Android 后端是 Windows 端核心模块的移植副本，而不是共享包依赖；因此同步必须通过差异审查和两端测试完成。

## 5. 启动、运行和关闭

### 5.1 数据根目录

数据根的优先级：

1. 设置了 `JMSHELF_DATA_DIR` 时使用该绝对路径。
2. 冻结后的 Windows 应用使用 `%LOCALAPPDATA%\JmShelf\data`。
3. 开发模式使用项目内 `data`。

HTTP 开发端口默认为 `17318`，可用 `JMSHELF_PORT` 覆盖。桌面模式不使用固定端口，而是先绑定回环地址上的空闲端口。

### 5.2 桌面启动过程

1. 创建 `Local\JmShelf.Desktop.Singleton.v2` Mutex。
2. 若已有实例且找到窗口，则恢复并前置既有窗口。
3. 冻结版首次运行时，必要时从项目开发数据安全迁移到 `%LOCALAPPDATA%`。
4. 创建 FastAPI 应用并在后台线程启动 Uvicorn。
5. 等待本地端口可连接。
6. 创建 1360×860、最小 920×620 的无框 WebView2 窗口。
7. 注入私有状态的 `DesktopApi`，加载 `/?desktop=1`。
8. 窗口显示后恢复 Windows 任务栏/最小化语义，并写入更新健康标记。

### 5.3 后端生命周期

FastAPI lifespan 启动来源系列更新线程，并调度 JMonline 首页榜单与推荐画像的后台快照刷新。已有快照会直接提供给 UI；画像只在首次生成、强制刷新或相对上次快照新增/变化至少 10 个来源 ID 时重算，因此进入页面不再同步挖掘整本书架。桌面模式还启动心跳看门狗：前端每 15 秒调用一次 `/api/heartbeat`，超过 90 秒未收到心跳时后端终止自身，避免 WebView 已消失但后台进程残留。

关闭时依次停止托盘、系列更新线程、缓存队列和下载队列。仅当所有工作线程都在超时内退出时关闭 SQLite，避免仍在运行的 provider 线程继续使用已关闭连接。

典型数据根包含：

## 7. SQLite 数据模型

数据库连接启用：

- `foreign_keys = ON`
- `journal_mode = WAL`
- `synchronous = NORMAL`
- `check_same_thread = False`，所有访问由 `threading.RLock` 串行保护。

### 7.1 `comics`

一行代表一本本地作品或 JM 的一话，而不是一个多话专辑。

| 字段 | 含义与约束 |
| --- | --- |
| `id` | 内部 UUID 主键，UI 和关系表只依赖它 |
| `source_id` | JM `photo_id`，唯一；远端章节身份以它为准 |
| `title` / `nickname` | 来源标题与用户昵称；显示名优先昵称 |
| `authors_json` / `tags_json` | JSON 数组 |
| `note` / `description` | 用户备注与来源描述 |
| `published_at` / `source_updated_at` | 来源时间文本 |
| `chapters_json` | 兼容字段；当前实际章节以独立记录表示 |
| `series_id` | JM 专辑/来源系列 ID |
| `series_title` | JM 专辑标题 |
| `chapter_index` | 整数或小数序号，仅排序与展示，不作为身份 |
| `root_path` | 本地图片根目录；在线未缓存记录可为空 |
| `cover_path` | 本地封面路径或预期封面缓存路径 |
| `storage_kind` | `local`、`download`、`cache`、`remote` |
| `cover_privacy_*` | 单本封面遮挡开关、方向和起点，起点限制 15–85 |
| `page_count` / `progress_page` | 页数和零基阅读进度 |
| `source_status` / `source_error` | `local`、`pending`、`matched` 等来源状态 |
| `created_at` / `updated_at` / `last_read_at` | UTC ISO 时间 |

核心不变量：

- 改昵称不会改变 `id`，因此不会破坏收藏夹、系列或进度。
- `source_id` 唯一；再次加入同一话会更新已有记录，而不是新增重复行。
- 相同章节序号但不同 `photo_id` 的补充话必须同时保留。
- `chapter_index` 支持 `1.2`、`27.5` 等小数。
- `remote` 表示只有元数据；`cache` 是可清理阅读缓存；`download` 是用户选择的长期副本；`local` 是导入目录。

### 7.2 `collections` 与 `comic_collections`

- `collections` 使用 UUID、`parent_id`、名称和同级排序值构成多级目录树。
- 外键删除采用级联；删除父目录会删除其子目录和关联关系，但不会删除漫画。
- 更新目录时用递归 CTE 阻止把目录移动到自己的后代下面。
- `comic_collections` 是多对多关系，一本可以同时出现在多个目录。
- 拖放批量归类每次最多处理 2000 本，且不会移除原有目录关系。
- 系列成员在收藏夹计数中按系列合并为一个书架对象。

### 7.3 `library_series` 与 `library_series_members`

`library_series` 是书架展示/更新订阅实体，与来源字段 `comics.series_id` 分层：

- `kind=custom`：用户手动选择至少两本组成，成员顺序由用户决定。
- `kind=source`：来自同一 JM 专辑，可只有一个成员，用于追踪未来更新。
- `displayAsSeries` 只有成员达到两本才为真；单话来源订阅不会强制显示成堆叠系列卡。
- `sourceSeriesId` 仅在所有成员都具有相同 `comics.series_id` 时成立。
- `library_series_members.comic_id` 全局唯一，一本不能同时属于两个书架系列。
- 来源系列成员按 `chapter_index` 再按原位置排序。
- `update_items_json` 保存远端存在但本地尚无的 `photo_id` 清单。

这套设计解决了“当前只有一话的作品无法进入后续更新链路”的问题：只要 provider 返回可靠的 `series_id`，单话也会建立隐藏的 `kind=source` 订阅；日后远端出现新的 `photo_id` 即可被发现。是否是连载不依赖标题或页数猜测，而依赖远端专辑身份与章节清单。短篇在没有新增章节时只是持续得到空更新结果。

### 7.4 `online_metadata_cache`

JMonline 的车牌、标题、作者、标签、日期、简介和页数使用独立表按需缓存，`album_id` 是整数主键。在线列表只把本次实际返回给 UI 的作品批量写入；搜索结果已有的部分信息先落库，详情补全成功后立即合并并标记 `details_complete`。再次出现相同车牌时按主键读取并直接补回标签，不扫描其他记录。

系统不会在启动时遍历远端目录，也不会把整个缓存表加载进内存。历史 `jmonline-metadata.json` 不做自动全量迁移，也不再由 provider 读取；这样升级后的首次启动不会为了旧缓存做一次 O(n) 遍历，新访问的作品会自然进入 SQLite。

### 7.5 `settings`

键值均以文本保存，目前正式键如下：

| 键 | 含义 | 默认值 |
| --- | --- | --- |
| `provider.optionPath` | 可选 `jmcomic` option 文件 | 空 |
| `provider.proxy` | HTTP/HTTPS/SOCKS 代理 | 空 |
| `download.defaultPath` | 长期下载默认目录 | 空 |
| `privacy.sanityMode` | 封面隐私模式 | `0` |

话数并行和每话图片并发均不再是用户设置：provider 根据任务规模自动使用 1–2 个话级 worker，并按当前页面焦点在每话 4、6、9、15、18、24 路之间选择候选并发；全局 24 路焦点感知门限仍负责最终网络占用。

### 7.6 数据迁移策略

当前没有独立 schema version 表。`LibraryDatabase._migrate()` 每次启动执行 `CREATE TABLE IF NOT EXISTS`，再通过 `PRAGMA table_info` 增补缺失列，并对历史数据做少量回填：

- 无本地路径且有来源 ID 的旧记录回填为 `remote`。
- 旧系列若成员全部属于同一来源专辑，回填为 `kind=source`。
- 启动时为已有的单话来源记录补建来源订阅。

以下偏好保存在 WebView/浏览器 `localStorage`，不会进入 SQLite：

| 键 | 用途 |

## 9. 功能设计与主要链路

### 9.1 本地目录导入

```text
选择目录
  ├─ 目录直接含图片 → 整个目录视为一本
  └─ 否则 → 每个含图片的一级子目录视为一本
       ↓
递归最多 4 层寻找图片，按自然数字顺序排序
       ↓
首图作为封面，图片数作为页数
       ↓
目录名纯数字 → sourceStatus=pending，并识别为 JM 车牌
其他名称       → sourceStatus=local
       ↓
upsert 到 SQLite，前端可继续自动匹配元数据
```

支持 JPG、JPEG、PNG、WebP、GIF、BMP 和 AVIF。

### 9.2 JM 查询与章节识别

`JmcomicProvider.lookup()` 同时查询用户输入对应的专辑与当前话，最多使用 4 路查询并发：

1. 规范化输入，提取至少三位数字的车牌。
2. 并行获取专辑和 `photo_id` 详情。
3. 若输入的是后续话且其 `album_id` 与初查专辑不同，重新获取真实专辑。
4. 使用自定义 album 类保留小数序号和同序号不同 `photo_id`。
5. 输入为首话/专辑 ID 时返回全系列；输入为明确的后续话 ID 时只返回该话。
6. 元数据缓存 15 分钟、最多 32 条；重复并行查询按分片锁合并。逐话缓存任务会复用同一系列查询结果，避免为每一话重复访问专辑详情。
7. 查询时可延迟封面，先返回结果，封面再通过媒体路由按需获取。

章节身份始终是 `photo_id`；章节序号只用于排序。这个约定不能在后续重构中改成按序号去重。

### 9.3 已有条目与幂等加入

数据库层根据 `id` 或唯一的 `source_id` 执行 upsert，因此重复加入同一话不会产生重复记录。JMonline 搜索与推荐卡片会预先标出“已在书架”和“已缓存”；旧的车牌查询弹窗仍会在点击后幂等更新既有记录并继续请求缓存，尚未补齐同级提示。

### 9.4 JM 收藏

1. 登录成功后把用户名、明文密码、服务端 cookies 和更新时间保存到本机 `jm-account.json`；每次启动立即在后台读取用户名和密码重新登录，成功后原子覆盖新 cookies。窗口与 JMonline 首屏不等待登录网络请求；收藏页会在首次访问时等待正在进行的会话刷新，避免拿旧 cookies 与自动登录竞态。
2. 如果只存在旧版 `jm-account.dat`，会用当前 Windows 用户的 DPAPI 解密一次并迁移为 JSON；新数据不再写 DPAPI 文件。
3. 收藏首页和其余分页最多 4 路并行抓取，结果缓存 5 分钟。
4. 后端把收藏按专辑 ID 与本地 `source_id`、`series_id` 合并。
5. 已存在作品返回本地记录；未存在作品返回远端占位卡。
6. “加入书架”会查询完整元数据、写入 `remote` 记录、建立来源系列订阅，并按章节拆成渐进缓存任务；每个系列第一话进入普通队列，后续话进入低优先级队列。后来加入作品的第一话可越过尚未开始的后续话，已经运行的下载不会中断。
7. “下载到书架”进入长期下载队列，不走缓存语义。

### 9.5 JMonline 首页、搜索与推荐画像

JMonline 是独立于本地书架和 JM 收藏的在线发现入口，内部保留“首页”“搜索”“分类”三个状态，但不再显示占空间的大 Hero 或顶部页签：

- 右下角悬浮按钮在首页显示搜索图标，点击直接进入搜索，悬停提供“搜索”和“分类”；搜索与分类状态显示主页图标，点击返回首页。其他主页面仍使用原有加号快捷添加菜单。
- 首页默认加载“猜你喜欢”，只展示推荐标签、更新时间、当前批次和“换一批”；可切换综合推荐、最佳匹配、最新发布和页数最多四种顺序。支持按名称查找并持久化排除不喜欢的标签，标签匹配不区分大小写，后端在分页前过滤以保证每批尽量填满。
- 分类是单独页面，集中展示全部 JM 分类，并提供独立排序、时间筛选、结果列表和分页；首页保留最新上架、今日热门、本周热门和本月热门。
- 搜索页支持综合、作品名、作者、标签和角色五种搜索域，支持 JM 的普通关键词、`+必须包含`、`-排除` 语法。
- 排序包括最新、观看、点赞、页数、评分和评论；分类包括全部、同人、单本、短篇、韩漫、美漫、Cosplay、3D、其他和英文站。
- 今天、本周、本月由上游直接筛选；近三个月、近一年和自定义日期在当前结果页补取发布日期后二次筛选，并在 UI 明示范围限制。
- 搜索页会把书架画像中的高权重标签和作者完整换行展示为较大的快捷入口；保留最近 8 条本机搜索历史，但没有历史时整组隐藏。旧的重复筛选摘要行已经移除。
- 在线列表直接读取上游的 `adddate` / `update_at`；历史推荐快照或其他缺少日期的条目按批次从 JM 网页详情补齐发布日期/更新时间，并立即按车牌写入 SQLite `online_metadata_cache`，相同作品后续通过主键命中。API 专辑详情中的日期固定为 `0`，不能再作为日期来源。
- 搜索、推荐、榜单和分类卡片会在展示后预取作者与标签：浏览器保持 4 个单本请求 worker，每一本返回后立即回填，不让慢作品阻塞整批卡片。服务端允许最多 6 路元数据查询，只合并同一本的重复请求，不再用全局锁串行不同作品；查询客户端按工作线程复用 curl-cffi Session。标签按钮可直接切到标签搜索，不需要先加入书架才能看到或使用标签。
- 在线详情提供独立“在线预览”：打开详情只补全元数据，不预加载图片；用户点击预览或选定章节后，才从 SQLite 复用首话/章节清单并开始图片加载。缓存缺失时先按“专辑车牌通常也是首话车牌”的常见形态直达章节，只有入口被拒绝才补查专辑。预览专用下载器并发获取章节详情与解码参数，并省去重复专辑请求。首段 4 页使用两个低延迟 CDN 竞速，到齐后立即打开阅读器；尾部按 4 页一段继续缓存，失败或单页响应超过 2.5 秒时让下一组跨 CDN 切换，并通过已完成文件清单增量公开，不反复扫描整个目录。预览写入 `cache/previews`，不创建书架记录。关闭阅读器后恢复原详情侧栏，用户可以继续决定是否加入书架。正在下载的预览始终受保护；空闲预览只保留最近 4 本，结束线程与失效会话会从内存登记中移除。
- 阅读禁漫书库的原生多话作品时，`POST /api/comics/{id}/read` 会查找当前话的下一话并自动加入书架缓存队列。已缓存的章节直接跳过；已排队或正在缓存的章节复用原任务并提升排队优先级，不启动重复下载。正在运行的当前话不会被打断，下一话仍受焦点带宽调度和最近 8 话缓存上限约束。
- 在线结果在进入详情前即合并本地状态；已经加入书架或已有缓存的作品不会伪装成全新条目。
- 用户界面只表达内容和操作，不展示“画像挖掘、加权、重排、快照、后台计算”等实现术语；这些细节只保留在本架构文档和内部数据结构中。
- provider 状态区分“组件已就绪”和“网络已连接”。实际查询会记录最近一次可达状态；未显式配置应用代理时，如果系统代理失效会自动回退直连，显式代理和 option 文件仍严格遵循用户配置。

推荐不是以“最近一本”为唯一种子，而是对整个现有书架做聚合：

1. 按 JM `seriesId` 合并同系列章节，避免多话作品因章节多而重复放大。
2. 标签和作者的基础频次按阅读次数、最近阅读的时间衰减、完成度、收藏夹归类共同加权。
3. 中文、汉化、全彩、无修正等泛化标签降权，作者信号略高于普通标签。
4. 取高权重作者和标签并行检索远端候选，排除书架里已有的 `sourceId/seriesId`。
5. 候选按画像重合度计分，再对重复作者和重复标签施加惩罚，生成更有差异的发现顺序。
6. 多样性排序后的候选按固定批次切片；“换一批”进入下一段，不再只是把同一组卡片轻微洗牌。
7. 后端仍保留推荐原因供调试和后续分析，但当前用户卡片不显示算法解释。
8. 完整候选池写入 `jmonline-recommendations.json`，记录生成时间和参与的来源 ID；启动与进入页面只读快照，不同步重算。
9. 相对上次快照累计至少 10 个新增/变化来源 ID 后，后台线程重新挖掘并原子替换快照；重算期间旧快照继续可用。
10. 首页榜单独立写入 `jmonline-home.json`，有效期 6 小时，过期后后台刷新，页面继续显示上一份快照。

画像只使用本地书架元数据和阅读行为，不上传额外用户画像；远端请求只是正常的作者/标签搜索。

### 9.6 阅读缓存与长期下载

两者复用 `DownloadQueue` 和 provider 下载实现，但业务语义不同：

| 项目 | 阅读缓存 | 长期下载 |
| --- | --- | --- |
| 队列状态文件 | `cache-queue.json` | `download-queue.json` |
| 默认位置 | `<data>/cache` | 设置目录或 `<data>/downloads` |
| `storageKind` | `cache` | `download` |
| 清理入口 | 右键“清除阅读缓存” | “删除本子与文件”；仅移出书架不会删除 |
| 用途 | 在线书架即时阅读，可回收 | 用户明确保存的离线副本 |
| 可选择章节 | 是，`selectedSourceIds` | 默认整次查询结果 |

手动批量缓存仍按 `seriesId` 分组，避免同一来源系列重复查询；在线作品“加入书架”采用逐话渐进任务。每话先以最多 4 路并发取得前 4 页，立即登记临时可读根目录并打开阅读器；余下页面继续并发下载，但只把从第 1 页开始连续完成的页数增量公开，避免乱序完成造成页码跳动。系列的首个待缓存章节使用普通优先级，后续章节使用后台优先级，因此新加入本子的首话会排在旧本尚未开始的后续话前面；运行中任务不抢占。用户点击尚未缓存的章节时，该章节会提升到队首；已有部分页面则直接打开并继续补齐。

图片传输使用 24 路焦点感知全局流量门。聚焦 JMonline 时，后台书架任务最多占 9 路，至少 15 路（62.5%）留给搜索、封面、标签和在线预览；进入预览时普通后台任务最多占 6 路，当前预览可使用最多 18 路；聚焦本地书架时，缓存与长期下载可使用最多 20 路（83.3%），空闲时仍能借满全部容量。已经传输中的图片不取消、不暂停，限额只影响尚未开始的请求。每话工作线程数由应用按焦点与任务类型选择，不再读取用户并发设置。在线列表和右侧详情都不下载预览页；用户点击预览或在禁漫书库中选定章节后才开始加载。进入预览后网络层按 4 页批次连续取回，界面同样以 4 页为一组公开；最后不足 4 页的一组在任务完成时公开。退出预览即取消尚未开始的尾段。元数据查询使用独立的 6 路优先级通道，并随焦点为交互请求保留容量；详情页请求使用交互优先级。

预览页可在“加入书架”后复用为正式阅读缓存的种子文件，避免相同页面再次下载；本地缓存仍按原始质量补齐。JMonline 的缩略图、按需元数据和预览目录均属于可清理临时缓存，清理入口不会触碰书架阅读缓存或用户选择目录中的长期下载。

### 9.7 下载器完整性

- 队列默认 2 个工作线程，最多允许配置到 4 个。
- 队列分普通与后台两级，级内保持 FIFO；优先操作只重排未开始任务，不取消或中断运行中任务。
- 相同 `sourceId + outputPath + context` 的活跃任务去重。
- 每个任务内部自动并行 1–2 话；每话图片并发由焦点和任务优先级自动决定，实际总占用受 24 路焦点感知门限控制。
- 普通下载与预览共用图片 CDN 健康状态：长期下载把首批图片分散到可用节点，单张图片失败后按不同域名依次尝试，不再由 jmcomic 对同一绝对 URL 重复重试。失败或响应过慢的节点暂时降权 120 秒；长期下载最多尝试 6 个节点，前台预览最多尝试 3 个节点。
- 图片请求逐次占用和释放流量门；预览首段的双节点竞速按实际两个请求分别计入限额。默认前台预览请求超时 8 秒，其余章节客户端请求超时 12 秒；用户配置的更短超时仍保留。
- 不同任务下载同一章节时按目标路径分片锁，避免并发写坏目录。
- 远端返回 0 页时最多更换客户端重试 3 次。
- 完成前核对远端预期页数和本地实际图片数；不完整即失败。
- 长期下载每完成一话就先验收并入库，队列用 `importedItems` 告知前端刷新书架；整项任务结束时仍对所有章节做最终核对。失败时已完整入库的章节不会被丢弃。
- 任务状态为 `queued`、`running`、`completed`、`failed`。
- 页级进度实时保存在内存，队列 JSON 最多约每 750 ms 重写一次；排队、开始、完成、失败与关闭状态仍立即落盘。
- 保留最近 40 个终态任务；异常退出后原活跃任务恢复为可重试失败态。
- 队列状态用临时文件替换方式写入；状态文件损坏不会阻止应用启动。

### 9.8 来源系列更新

`SeriesUpdateChecker` 的设计：

- 应用启动约 2 秒后，对所有可更新来源系列强制检查一次。
- 启动检查最多 4 路并行。
- 后台每 15 分钟轮询一次是否到期；同一系列默认 24 小时检查一次。
- 检查仅抓取轻量章节清单，不下载图片和封面。
- 以远端 `photo_id` 与本地成员的 `source_id` 做差集。
- 手动刷新系列时，把缺失话放入缓存队列或下载队列。
- 如果系列成员全部是 `cache/remote`，新话继续进入缓存；只要存在长期本地/下载成员，新话进入下载目录。
- 检查失败写入 `update_error`，不阻断其他系列。

### 9.9 自建系列

- 至少选择两本，点击顺序决定成员顺序。
- 第一本决定默认系列名称和主封面。
- 书架以堆叠封面显示，系列内再选择具体成员阅读。
- 继续阅读定位到 `last_read_at` 最新的成员。
- 解除系列默认只删除关系；也可选择连同所有成员及其当前存储一起删除。
- 一本书架记录不能同时加入多个 `library_series`。

### 9.10 收藏夹与书架呈现

- 固定入口：全部本子、JMonline、JM 收藏、未分类。
- 用户目录支持任意层级、重命名、移动和级联删除目录。
- 漫画或系列卡可拖入目录；系列按成员批量建立关系。
- 即时搜索覆盖标题、昵称、作者、标签和车牌，输入防抖 180 ms。
- 书架类型快捷筛选：全部、自建系列、来源系列、单行本。
- 排序支持最新更新、未读优先、最常阅读、最近阅读、最近加入、标题、页数和默认顺序。
- 卡片密度保存在浏览器偏好中。

### 9.11 详情页与纯净模式

详情抽屉提供昵称、备注、收藏夹、来源元数据、封面更换和删除操作。抽屉本身是固定高度的纵向 flex 容器，封面不压缩，`detail-body` 以 `min-height: 0` 占据剩余空间并独立纵向滚动，避免右侧内容超出后无法操作。封面渐变亚克力参数按本保存。

全局 `sanityMode` 控制书架封面是否实际显示隐私遮挡；详情页可强制预览本书的遮挡结果。相关编辑设置仅应在纯净模式开启时暴露，后续 UI 修改需同时验证这一可见性规则。

### 9.12 阅读器

| 模式 | 行为 |
| --- | --- |
| 连续滑动 | 所有页面纵向排列，IntersectionObserver 保存当前页 |
| 单页翻页 | 仅显示当前页，按钮/方向键/PageUp/PageDown 翻页 |
| 双页书本 | 每次显示两页，可切换左页或右页为前进方向 |

补充能力：

- 自动阅读仅用于连续模式，支持连续匀速和分段翻屏。
- 速度分慢、普通、快；用户滚轮、指针或导航操作会暂停。
- 页码保存有 250–600 ms 防抖，关闭或切话时立即补保存。
- 系列阅读器包含章节目录、上一话/下一话和下一话图片预取。
- 翻到本话边界时自动进入相邻话。
- `[` / `]` 切话，`Esc` 按上下文关闭菜单、弹窗、阅读器或详情。

### 9.13 右键菜单

前端用一个自定义 `#context-menu` 和动作数组实现，不依赖浏览器原生菜单。当前管理面包括：

- 普通漫画：阅读、详情、系列、待读、目录、缓存管理、资源管理器、更新信息、复制、删除。
- JM 远端收藏：详情、加入书架并缓存、长期下载、复制车牌。
- 系列：打开、继续阅读、主本详情、待读、目录、缓存、更新、复制来源 ID、解除/移除。
- 收藏夹：打开、新建子目录/同级目录、重命名/移动、删除。
- 固定分类：刷新收藏、账号、导入、查车牌、添加系列、新建目录。

### 9.14 桌面窗口与隐私操作

- Web 页面内绘制最小化、最大化/还原和关闭按钮。
- `DesktopApi` 通过 Win32 设置工作区最大化，避免无框窗覆盖任务栏。
- 八个透明边缘支持原生缩放，最小尺寸 920×620。
- 页面拖拽区通过 JS bridge 触发 `WM_NCLBUTTONDOWN`。
- “跑路”按钮、鼠标中键或 `Ctrl+Shift+H` 把窗口隐藏到系统托盘。
- 托盘只有“显示 JmShelf”，恢复后销毁托盘图标。

### 9.15 主题与图标

## 10. 前端结构

### 10.1 页面区域

`index.html` 预先声明以下主要区域：

- 左侧栏：品牌、固定分类、用户目录、账号、设置。
- 顶栏：搜索、主题按钮、Windows 窗口控制。
- 主书架：标题、排序、筛选、密度、漫画/系列网格和空状态。
- JMonline：猜你喜欢与多维榜单、独立分类页、悬浮式首页/搜索/分类切换、在线搜索筛选、历史与结果分页；进入入口和内部换页都有过渡动画。
- 悬浮区：添加菜单、下载队列预览、托盘隐藏。
- 详情抽屉与遮罩。
- 自定义右键菜单。
- 查询、设置、登录、更新、关于、目录、确认、系列编辑、系列查看等模态层。
- 全屏阅读器、章节抽屉、自动阅读控制和翻页按钮。
- Toast 栈。

### 10.2 状态模型

`app.js` 使用单一可变 `state` 对象管理：

- 漫画、系列、收藏夹、JM 收藏、JMonline 搜索/推荐/画像/榜单/分类/日期补全、设置和 provider 状态。
- 当前分类、筛选、详情、系列、查询和编辑选择。
- 阅读器页面、模式、进度、自动滚动、章节和预取。
- 下载/缓存队列及轮询锁。
- 应用更新状态。
- 拖放、右键动作、确认 Promise 和各种计时器。

没有组件框架和响应式数据层；状态变化后由相应 `render*` 或 `load*` 函数显式更新 DOM。

### 10.3 事件模型

- 大部分动态按钮使用 `data-action` 和 document 级事件委托。
- 右键动作保存在 `state.contextActions`，DOM 仅保存数组索引。
- 卡片点击、系列点击、阅读页点击、拖放和右键菜单分别委托到稳定容器。
- 静态表单和按钮直接绑定事件。
- 原生窗口桥在 `pywebviewready` 后激活；Android 主题桥使用可选链，不存在时安全忽略。

### 10.4 初始化和轮询

初始化并行获取设置、收藏夹、书架、系列、provider、下载队列和缓存队列。JMonline 的推荐、首页榜单和作品日期只在进入该入口后读取本机快照或按需补全；后端刷新线程不阻塞初始化响应。其后：

- 每 15 秒发送桌面心跳。
- 每 1.1 秒轮询下载队列。
- 每 1.1 秒轮询缓存队列。
- 启动 450 ms 后执行网络型启动任务，包括应用更新与来源更新提示。
- 每 60 秒刷新系列状态，但签名未变化时跳过重绘。

## 12. 文件删除与安全边界

### 12.1 当前删除语义

当前 `DELETE /api/comics/{id}` 默认只删除书架记录、收藏关系和系列成员关系，不删除 `root_path`。详情页和右键菜单会让用户在“仅移出书架”与“删除本子与文件”之间明确选择；只有传入 `deleteFiles=true` 才进入文件删除流程：

1. 阻止删除仍有下载/缓存任务的来源。
2. 拒绝符号链接、junction、磁盘根、用户主目录、项目源码目录、数据根、缓存根本身和配置的下载根本身。
3. 拒绝与其他书架条目共享、包含或被包含的目录。
4. 先把所有目标原子改名到同级隔离目录。
5. 使用事务删除数据库记录；失败时恢复原目录名。
6. 数据库成功后递归清理隔离目录，并返回未清理成功的路径。

“仅移出书架”同样拒绝正在下载或缓存的来源，防止任务完成后条目被重新写回；文件删除继续使用上述隔离、事务和恢复流程。

### 12.2 本地 HTTP 防护

- 服务只绑定 `127.0.0.1`。
- 修改型 API 要求自定义请求头，降低普通网页表单误触风险。
- 该请求头不是身份认证；若未来允许局域网访问，必须加入真正的随机令牌、Origin 校验和授权。
- 媒体页解析最终路径并确认其仍在漫画根目录下。
- 缓存清理只能删除 `<data>/cache` 内部的后代目录。

### 12.3 凭据

- Windows 端把用户名、明文密码、cookies 和更新时间写入数据根的 `jm-account.json`。每次构造 provider 配置时读取本机 cookies，同时应用启动后用已保存用户名/密码在后台主动登录并更新文件；退出登录与自动恢复使用同一把锁，避免退出时旧任务重新写回凭据。
- 这是产品当前明确接受的低保护方案：任何能读取当前用户数据目录的进程都能看到账号信息；文件不得进入发布包、日志或版本控制。
- 旧 `jm-account.dat` 仍可由原 Windows 用户通过 DPAPI 解密一次并迁移；退出登录会同时删除 JSON 与旧 DAT。
- Android 使用自己的凭据实现，不直接复制 Windows `jm-account.json`。

## 13. 应用更新设计

默认清单地址：`https://apps.usotsuki-kaze.com/releases/jmshelf/stable/latest.json`。

更新检查和下载规则：

- 清单最大 512 KiB。
- 版本号、HTTPS、同域 ZIP、声明大小和 SHA-256 均需合法。
- 下载最多重试 4 次，支持 HTTP Range 续传。
- 下载后同时校验长度与 SHA-256。
- ZIP 拒绝绝对路径、`..`、符号链接和超过 1.5 GiB 的解压总量。
- 包内顶层必须是 `JmShelf/`，且必须含主程序、独立更新器和 `_internal`。

应用过程：

1. 将随包更新器复制到数据目录，写入 apply plan。
2. 更新器先把新文件复制到安装磁盘的 incoming 目录。
3. 报告 ready，等待旧进程退出。
4. 把当前程序文件移到 backup，再把 incoming 移入安装目录。
5. 启动新版并等待窗口显示后写入的健康标记。
6. 健康检查成功后清理备份；失败则恢复旧版并重新启动。

安装器卸载信息不在程序目录的替换列表中，因此文件级更新不会破坏 Inno Setup 注册信息。

## 16. Windows 与 Android 同步边界

### 16.1 当前关系

- `index.html`、`styles.css`、`app.js` 在两端不是逐字相同：Android 包含移动布局、原生桥和平台功能裁剪。
- `ukp.png` 当前两端哈希一致。
- Windows `public/icons` 当前有 38 个 SVG，Android 为 28 个；Windows 额外使用 `home.svg` 作为 JMonline 悬浮导航，并使用专用的纵向连续、单页、双页图标。若 Android 后续接入同一页面需按共享 UI 清单同步。
- Windows 的托盘、跑路、无框窗口和应用文件替换不应复制到 Android。
- Android 的 SAF、外部存储授权、移动端导航、原生图片解码和 APK 更新不应复制回 Windows。
- 数据库、provider、下载和来源更新的业务不变量应尽量一致，但当前是复制代码，需人工同步。

### 16.2 每次共同功能修改的同步清单

1. 判断改动属于共享业务、共享 UI、Windows 专属还是 Android 专属。
2. 共享业务同时比对 `db/provider/downloads/updates/importer/utils`。
3. 共享 UI 同时比对 HTML 语义、动作名、CSS 变量和图标映射，不要直接覆盖移动端布局。
4. 新增 API 时确认 Android server 是否需要同一路径与返回形状。
5. 新增设置时决定它属于 SQLite 共享设置还是平台偏好。
6. 新增图标时从外部完整图库按需复制，并同步许可证/来源映射。
7. 分别运行 Windows pytest 和 Android 测试/构建。
8. 比较两端品牌资源和图标哈希；允许入口文件因平台适配而不同。

## 18. 已知架构债务与改进优先级

### 18.1 1.3.0 已完成的 P1

2. 缓存和在线预览在首屏就绪后按连续页序增量公开尾页。

5. 单本操作拆为“仅移出书架”和“删除本子与文件”，默认 API 采用安全的仅移出语义。

### 18.2 1.3.1 预览与元数据提速

1. `online_metadata_cache` 增加首话 ID 与精简章节清单，按车牌增量写入；后续预览可直接从 SQLite 命中，不再重复获取专辑结构。
2. 标签补全改为 4 路单本 worker，单卡完成即更新界面；失败或慢响应不再拖住同批所有卡片。
3. 预览专用下载路径并发请求章节详情与 scramble 参数，并以本地固定目录规则避免下载器再次获取专辑详情。
4. 首段由 1 页改为 4 页并行并对两个优选图片 CDN 做竞速，尾部按 4 页稳定分段缓存；前端首次轮询从固定 450 ms 改为 100–220 ms 自适应等待，后续页面以 220–500 ms 自适应追加。
5. 预览会话保存连续页文件清单，状态查询和媒体读取优先复用清单，减少反复遍历磁盘。
6. JM 登录凭据启动时从本地 JSON 读取并在后台主动刷新会话；新 cookies 成功后写回，登录网络耗时不计入窗口启动时间。
7. “猜你喜欢”增加标签排除面板，可搜索已有标签或直接输入标签；选择结果保存在本机，大小写不敏感，并在推荐排序完成、批次分页开始前统一过滤。
8. 在线列表封面优先直连实测较快的 JM `_3x4` 小图，失败时自动回落到本地代理缩略图；缩略图独立缓存并复用网络会话，首屏 8 张封面使用高加载优先级。
9. 标签补全改为首屏优先的 5 路 I/O 队列，屏幕外卡片通过 `IntersectionObserver` 在接近视口时加载；不使用额外进程，避免重复客户端和内存开销。
10. 图片忙时调度区分预览首段、预览尾段、可见封面和后台任务；预览期间普通下载最多占 6 路，已开始的图片不打断，新任务自动让路。
11. 移除“每任务并行话数”和“每话图片并发”用户设置，两级并行均改为内部自动调度；聚焦 JMonline/本地书架时分别保证至少 60%/80% 的图片通道供当前场景使用。

### 18.3 1.3.2 正确性与缓存边界

1. 修复预览清理函数注册早于定义导致应用创建失败的问题，并增加完整启动回归。
2. 同一本在线作品切换章节时使用会话令牌隔离工作线程；旧章节即使未及时响应取消，也不能覆盖新章节的页面、状态或错误。
3. 打开右侧详情只加载元数据；禁漫书库必须先选择章节，普通作品必须点击预览，才建立预览缓存。
4. 在线预览只保留最近 4 本；书架阅读缓存只保留最近 8 话，禁漫书库按单话计数并共享同一缓存池。长期下载与本地导入不参与自动清理。

### 18.5 仍需持续处理的架构债务

1. **API 请求模型大量使用裸 `dict[str, Any]`。** 缺少集中 schema、字段白名单和 OpenAPI 约束，未来字段演进容易出现静默拼写错误。应引入 Pydantic 请求/响应模型。
2. **数据库迁移没有版本账本。** 目前按列存在性增补，无法表达复杂回滚、数据修复是否已执行以及迁移失败恢复。应增加 `schema_migrations` 和备份/校验流程。
3. **Windows 与 Android 复制核心代码。** 修复很容易只落在一端。应提取可共享的纯 Python 核心包，或至少建立自动差异检查和同步清单测试。
4. **应用更新只有同域清单 + SHA-256，没有独立签名。** 若发布站点被完全控制，攻击者可同时替换清单和包。长期应增加离线公钥签名验证。

### 18.6 P2：中期改进

1. **前端单文件过大。** `app.js`、`styles.css` 和 `main.py` 都是高耦合单体；应按书架、详情、阅读器、下载、更新、桌面桥拆模块。
2. **队列状态持久化错误被静默忽略。** 磁盘满或权限错误时用户不知道任务历史无法保存；应暴露健康状态或日志。
3. **前端依赖高频轮询。** 下载与缓存各 1.1 秒轮询；可改为 SSE/WebSocket 或统一长轮询，减少无变化请求。
4. **异常信息直接返回给前端。** 当前通用异常会返回 `str(exc)`，可能暴露本地路径或内部细节；应区分用户消息与诊断日志。
5. **完整 UI 图标来源未在仓库内固定映射。** 应增加小型 manifest，记录上游提交、原名、许可证和本地自绘图标，但仍不提交全库。
6. **WebView 运行目录容易被误当源码。** `webview/` 当前存在于项目工作目录但未写入 `.gitignore`；应加入忽略规则或只使用 `%LOCALAPPDATA%`。

### 18.7 P3：体验与维护性

1. 增加真实浏览器 E2E、视觉快照、键盘焦点和无障碍测试。
2. 给主题色、间距、层级、动画时长建立更完整的 design token 层。
3. 给 API 和前端动作生成机器可读清单，减少手写契约测试。
4. 为真实 JM 接口增加可选的受控烟雾测试，明确不进入默认 CI。
5. 给本地图库增加只读搜索/预览脚本，避免手工遍历 815 个图标。
